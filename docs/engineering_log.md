## 2026-10-24: Showcase build

**Inventory.** Every source file was hashed before copying. Two duplicates were resolved (see [notebook_map.md](notebook_map.md)). Two findings came out of the inventory:

1. The Week 6 operations notebook as saved selects threshold 0.40, while the submitted reports quote 0.39. The 0.39 figures come from the team's Colab run (2026-08-08); the saved notebook and the exported model come from a local re-run (2026-08-17). Decision: use 0.40 everywhere, keep both runs' files, and say so on the site.
2. The same re-run overwrote the Week 5 financial result CSVs (now XGBoost F1 0.533, RF 0.472). The official XGBoost 0.529 survives in `week6_financial_tuning_results.csv`; RF 0.489 only in the Final Report's tables. `scripts/extract_report_tables.py` was written to read those tables by code instead of retyping them.

**Notebook 07.** Scores both test sets with the exported models and checks them against the Week 6 files: operations precision, recall, F1, ROC-AUC, PR-AUC within 1e-8, both confusion matrices exact. Financial F1 reproduces the documented 0.5333.

- **Rounding bug caught by an assert.** Probabilities rounded to 4 decimals moved 4 orders across 0.40; at 6 decimals, 3 orders still moved across some 0.01 step, because Random Forest averages land just below round numbers (for example 0.39999999999999997). Probabilities are now stored at full precision and the notebook re-reads the file to prove no order changes side at any slider step.
- **New artifact mismatch.** Rebuilding the raw operations test split and transforming it with the Week 4 preprocessor matched the `_v2` test file on 26 of 27 columns exactly. `Order Item Profit Ratio` differed on every row. The `_v2` data caps it at the training IQR bounds and standard-scales the capped values; the recovered transform reproduces all 34,393 values (residual 4e-16). The Final Report text also says Profit Ratio was IQR-clipped, which fits the `_v2` data rather than the exported preprocessor. Impact on the 8 demo orders: at most 0.009, no decision changes (notebook 06).
- **SHAP checks.** All 24 financial and 40 operations exported cases reconcile within 1e-6 (largest 3.9e-7 and 4e-13). Every `.pkl` hash is identical before and after.

**What-if parity.** The JavaScript XGBoost scorer matched Python on all 1,364 test firms; largest difference 6e-8. The feature shipped.

**Notebook 06.** Re-runs the three demo scripts from `scripts/` with only folder constants swapped (and the operations threshold changed from the archived 0.39 to 0.40, printed). Re-run SHAP tables match the committed August tables exactly.

**Fact checks while writing.** A bootstrap first described as "change in F1" was on PR-AUC; corrected. The claim that scheduled days and shipping mode are "almost" collinear was checked on the full DataCo file: each mode has exactly one scheduled window, so the wording became "the same information".

**Report PDFs.** Word automation hung on a hidden dialog; LibreOffice headless exported all six reports. Pages with figures were spot-checked.
