What we did, layer by layer

Financial (Taiwan bankruptcy)

  • Capped the lightly damaged ratios at their 99th percentile and dropped the columns where most values were placeholders.
  • Built two composite features from related ratios, such as an average of three return-on-assets measures.
  • Split 80/20 with stratification, so both sides keep the same {{ facts.financial.bankrupt_rate | pct1 }} bankruptcy rate, then scaled using the training split only.

Operations (DataCo orders)

  • Removed personal data (names, emails, passwords, street addresses), free text, and duplicate ID columns.

The rule that held everything together

Split first, then fit. Every step that learns something from data (capping thresholds, clipping bounds, scalers, one-hot vocabularies, target encodings) was fitted on the training split and only applied to the test split. If any of them had seen the test data, the test scores would have been quietly optimistic.

Checks the pipeline had to pass

The integration notebook stops with an error unless all of these hold, for both layers:

  • no missing values in the processed training or test matrices;
  • every value finite (no infinities left over from ratios);
  • training and test matrices have the same columns.

These are the assert statements in notebook 03 (cells 10 and 32). An earlier, superseded pipeline run also left a checks file in the course folder; it isn't used here because it belongs to a different column set.

A leak we only caught later

Week 4 kept eight Order Status columns, reasoning that an order's status is known before delivery. In Week 6 the team looked again and judged they could carry information about how the delivery turned out, so they were dropped. The operations model went from {{ facts.operations.processed_features | int }} inputs to {{ facts.operations.model_features | int }}. The Week 5 operations results on the next page were measured before that fix, which is why the final operations numbers come from Week 6.
