Reconciliation

Report, presentation and repo, side by side

The class report, the final class presentation and this site were built at different times, from different runs. This page lines their numbers up, shows where they agree, and explains each difference.

Short version. All three agree on the data: the same firms, orders and splits. They agree on the operations model, apart from rounding and the threshold the re-run chose. They differ on the financial headline: the report says F1 {{ cmp.financial.0.f1 | f3 }}, the presentation says {{ cmp.financial.1.f1 | f3 }}, and a fresh local run gives {{ cmp.financial.2.f1 | f3 }}. Each number is real. They come from three different fits of the same model.

Why the numbers differ

  • Report ({{ cmp.financial.0.f1 | f3 }}). {{ cmp.financial.0.note }}. This is the official figure and the one every report table uses.
  • Presentation ({{ cmp.financial.1.f1 | f3 }}). {{ cmp.financial.1.note }}. Its counts ({{ cmp.financial.1.tp | int }} caught, {{ cmp.financial.1.fp | int }} false alarms, {{ cmp.financial.1.fn | int }} missed, {{ cmp.financial.1.tn | int }} cleared) match that Week 6 row exactly. The model settings are the same; the training rows are not. On {{ facts.financial.test_bankrupt | int }} bankrupt firms, two extra catches move F1 by about four points.
  • This repo ({{ cmp.financial.2.f1 | f3 }}). {{ cmp.financial.2.note }}. This is the file the console scores, so it's the one you can run yourself.

None of these is wrong, and with this few positives none of them can be called better. For any graded or quoted claim, the report's {{ cmp.financial.0.f1 | f3 }} is the figure to use.

The only real difference is the threshold. The Colab run's validation search picked {{ cmp.operations.0.threshold | t2 }}. The saved notebook, re-run locally to export the final model, picked {{ cmp.operations.2.threshold | t2 }}. Validation F1 at the two thresholds is nearly identical (about {{ val.f1 | f3 }} at both), which is why a small change in library versions flipped the pick. The trade-off reads the same either way: far more late orders caught, at the cost of more false alarms.
